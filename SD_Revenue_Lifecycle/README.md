# ZSD_REV_LIFECYCLE_EXTRACT

面向 SAP ECC 的长期订单收入审计取数模板。它不是现有 KAAP XML 的简单改期版本，而是将“订单—交货—凭证流—多次开票/红冲/重开—FI 暂估及冲回”作为事件链取数。

代码按 ABAP 7.40 语法准备；客户若为较早 ECC/NetWeaver 版本，应先在开发客户端语法检查，并视需要将 RTTI CSV 序列化和 `STRING` 参数改为客户现有 KAAP 兼容写法。

## 适用场景

- 一个客户订单持续 3–4 年；
- 同一订单行分批交货、验收和开票；
- 期间存在红冲、贷项/借项或重新开票；
- 未开票时先暂估收入，开票后暂估冲回；
- 需要在审计截止日判断累计已开票、累计暂估和未核销暂估。

## 与原 SD XML 的差异

原工具适合订单/发货/开票三单匹配。本工具增加了：

1. 以订单、开票或 FI 过账期间作为种子人口；
2. 通过 `VBFA` 双向扩展最多 20 轮，追溯历史及后续单据；
3. 不在 SAP 端将多张发票净额化，每张 `VBRP` 行单独输出；
4. 保留 `VBRK-FKSTO/SFAKN`、借贷方向、FI 参考字段和冲销/清账字段；
5. 额外输出 `BKPF/BSEG`，用于暂估收入及暂估冲回分析；
6. 输出控制文件，便于按公司、币种和数据集核对行数及金额。

## 输出文件

每次运行按时间戳输出：

- `*_order_item.csv`
- `*_delivery_item.csv`
- `*_billing_event.csv`
- `*_document_flow.csv`
- `*_fi_header.csv`
- `*_fi_line.csv`
- `*_control.csv`

文件使用 UTF-8 和 `#|#` 分隔符。原始金额、数量、币种和 `SHKZG` 均保留，不在 ABAP 中替换为审计结论。

## 使用步骤

1. 将 `zsd_rev_lifecycle_extract.prog.abap` 复制到客户 ECC 的自定义可执行程序中，例如 `SE38` 创建 `ZSD_REV_LIFECYCLE_EXTRACT`。
2. 先在开发/测试客户端运行，输入目标公司代码、审计期间及应用服务器输出目录。
3. 推荐第一次使用“发票种子”模式：输入 `VBRK-FKDAT` 审计期间，程序会追溯相关订单和历史凭证流。
4. 为收入暂估测试勾选 FI 期间取数，并输入暂估/收入确认总账科目范围 `BSEG-HKONT`。
5. 对输出文件执行行数、金额、币种、重复键、前导零、凭证流闭环和 FI 借贷平衡检查。

## 重要配置边界

- 当前程序只使用 SAP 标准 SD/FI 表；客户验收单、收入确认程序结果或 Z 表尚未纳入。
- `FORM CUSTOMER_EXTENSION` 是预留扩展点。取得客户表结构后，应增加订单/订单行、验收日期、确认金额、暂估凭证号和冲回凭证号。
- 订单金额 `VBAP-NETWR` 不自动等同于法律合同金额。若合同金额来自合同单据、定价条件或外部系统，应增加对应数据源。
- `VBFA` 最多扩展 20 轮；若出现警告，必须检查是否存在长链、循环或数据量过大的凭证流。
- 老凭证如果已归档，需确认客户的 Archive Information System/归档读取权限。XML 中存在归档对象声明，不等于本程序已经完成归档数据读取。
- `BSEG` 在 ECC 中可能是高容量/集群数据。正式运行前应限制公司代码、过账期间和总账科目，并先以小范围抽样验证。
- 程序输出的是取证底稿原始层；红冲与重开票的有效性、暂估是否应冲回、收入确认是否符合会计政策，需要在下游规则中判断。

## 推荐后处理规则

下游程序应保留事件级数据，并按以下顺序处理：

1. 先识别原始发票、红冲、贷项、借项和重新开票；
2. 优先使用 SAP 明确关联字段及 `VBFA`，再使用订单行、客户、物料、金额和日期推导；
3. 区分系统直接关联、规则推导关联和人工支持；
4. 计算累计暂估、累计冲回、有效开票净额和截止日未核销暂估；
5. 对一对多、多对一、未匹配和跨期间项目单独输出。

## 尚未完成的客户化工作

本交付不假定客户的：

- 收入暂估总账科目；
- 暂估凭证类型及冲回凭证类型；
- 验收单/项目确认单的表名和键；
- 开票、红冲和重开票的业务类型映射；
- 合同金额的系统来源；
- SAP 归档范围及历史保留期限。

上述信息确认后，应再开发客户化扩展，并用至少一笔“暂估—开票—红冲—重开—冲回”的完整样本进行联调。
